최신 사용자 요청: 개인용 업무 화면에서는 익명 번호와 분류어만 보이지 않도록 한다. 상세 주소, 연락처, 전달받은 작업 내역과 금액 조건을 가능한 한 원문 그대로 표시한다. 공개 소스 저장소에는 실제 업무 자료를 포함하지 않는다. 외부 사이트에 적용하기 전 지정 계정 접근 설정을 확인해야 한다. 현재 세션에서는 해당 사이트의 접근 확인·배포 도구를 사용할 수 없어 외부 적용은 보류한다. 기존 익명 데이터는 삭제하지 않는다.

## 최우선 방향 — 2026-09-21: 수개월간 혼자 실사용

긴 대화 업로드 보완: 화면은 2MB 자료를 받지만 내부 원문 저장은 20만 자에서 거절하던 불일치를 해소했다. 일정 자료는 UTF-8 2MB 이내에서 원문을 분할하지 않고 보존하며, 직접 호출에도 같은 용량 제한을 적용한다. 일반 메모의 기존 제한은 유지한다. DOCX 업로드나 후속 대화 자동 해석까지 추가한 것은 아니다.

2026-09-22 연결 검증: 승인된 작업 일정 상세에서 같은 현장의 자유 일지로 바로 이어진다. 현장 기록·지출도 바로 열 수 있다. 취소된 작업이나 미확정 후보는 작업 기록 시작 동작을 노출하지 않는다. 일지 날짜는 오늘 기본값을 유지하고 실제 작업 날짜를 사용자가 조정한다. 방문은 방문 결과 경로를 유지한다. 허구 카톡 공사 픽스 → 작업 상세 → 현장 지정 자유 일지 → 명확한 주유비 지출 반영을 통합 시험한다. 카톡 업체금액은 실제 비용으로 합산되지 않는지 함께 확인한다.

사용자의 최신 결정에 따라 공동 사용·초대 관리·동시 편집 개발을 보류한다. 당장은 한 사람이 자료 전달부터 현장 확인, 자유 일지, 실제 지출 파악까지 이어서 사용하는 것이 목표다. 아래 공동 업무 구상은 미래 참고이며 현재 개발 우선순위가 아니다. PC/휴대폰 간 본인 자료 접근은 향후 비공개 운영 환경을 결정한 뒤 연결한다. 기존 사이트 접근 권한은 변경하지 않는다.

이번 연결: 현장 상세에서 작업일지를 열면 해당 현장 ID와 이름이 이어진다. 같은 이름의 다른 현장에 기록·지출을 잘못 연결하지 않는다. 일반 입력에서 동명 현장이 여러 개면 저장 전 해당 현장을 선택하도록 안내하고 원문을 보존하지 않은 채 잘못 등록하지 않는다. 오류 시 작성 내용은 입력창에 유지한다. 실제 원장 일괄 수정은 하지 않는다.

## 보류된 방향 — 2026-09-21: 초대형 공동 업무 앱

외부 접속의 목적은 공개 시연이 아니라 운영자와 초대받은 동료가 같은 실제 업무 자료를 사용하는 것이다. 이전 공개 시연판 확장보다 이 방향을 우선한다. 공개 소스와 비공개 업무 데이터는 별개다.

- 하나의 업무 공간: 자료 전달 → 같은 현장 → 방문/작업 일정 → 기록/지출을 PC와 휴대폰에서 공유한다.
- 링크만으로 접근할 수 없어야 한다. 인증된 초대 계정만 페이지, 데이터 요청, 원본 다운로드에 접근한다.
- 사이트 편집 권한과 앱 내부 기록 수정 권한은 별개다. 동료가 기록도 수정할지는 별도로 정한다.
- 중앙 저장소가 원장이며 로컬 원본은 이관 검증이 끝날 때까지 보존한다. DB 파일을 파일 동기화로 공유하거나 양쪽 원장을 동시에 수정하지 않는다.
- 여러 사람이 수정할 때 이전 버전 확인, 충돌 안내, 작성자와 수정 이력을 보존한다.
- 미수금·결제단계·중개수수료 메뉴는 추가하지 않는다. 기존 업무 흐름을 이동한다.

현재 외부 시연판의 접근 설정은 공개에서 소유자만 허용하는 지정인 접근으로 변경했다. 외부 이메일 초대 기능은 지원되지만 아직 동료를 초대하지 않았다. 시연판의 자료는 익명화된 읽기 전용 스냅샷이며 실제 앱과 연결되지 않았다.

### 구현 순서와 통과 조건

1. 초대 대상과 보기/수정 범위를 확인한다. 기존 사이트의 접근 제한을 유지한다.
2. 기존 Python 앱을 유지할 비공개 서버와 인증 경로를 선택한다. 현재 Sites 정적 시연판에 로컬 앱을 그대로 올릴 수 있다고 가정하지 않는다. 새 서비스·비용·실제 자료 전송은 승인 후 진행한다.
3. 허구 자료로 로그인한 두 사람의 동일 일정 조회, 수정 반영, 미초대 접근 거절, 원본 접근 거절, 동시 수정 충돌, 초대 회수와 백업 복원을 검증한다.
4. 검증된 경로로만 실제 자료를 이관한다. 건수·현장 연결·원본 해시를 비교한 후 주 원장을 전환한다.

현재 로컬 앱에는 사용자별 인증과 온라인 공동 저장 경로가 없다. 로컬 전용 실행 제한을 해제하거나 단순 공개 터널로 실제 DB를 노출하지 않는다. 접근 설정 변경만으로 공동 업무 앱 완성을 선언하지 않는다.

## 구현 진행 — 2026-09-16

### 일정 날짜 해석 보완

동월 기간 표기(8월 25일~28일), 반 시각(오후 1시 반), 차주/다음 주 요일을 지원한다. 차주는 발송일이 속한 주의 다음 주를 기준으로 한다. 존재하지 않는 날짜·역전된 기간·유효하지 않은 시각은 일정으로 만들지 않는다. 이 개선은 날짜 표현의 해석이며 후속 취소 메시지 연결이나 명시 날짜·요일·상대 날짜 충돌 해결까지 완성한 것은 아니다.

### 확정 방문의 현장 연결 (후속 구현)

지정 담당자의 픽스 방문을 가져올 때 견적 단계의 현장을 연결한다. 이미 가져온 미연결 방문은 재수입할 때 연결하고 기존 일정·금액을 중복하지 않는다. 현장명·전체 주소·작업 내용이 모두 같고 진행 중인 후보가 정확히 하나일 때만 재사용한다. 나머지는 별도 현장으로 보존하여 주소만 같은 다른 공사를 합치지 않는다. 방문 연결은 수주 확정이나 지출 등록을 뜻하지 않는다. 이전 데이터의 일괄 변경은 수행하지 않았다. 별칭·변경된 범위의 동일 현장 추론과 사용자 병합 기능은 후속 과제다.

### 카톡 자료 우선순위

카톡은 방문·작업 일정과 확인된 금액을 중심으로 처리한다. 실제 투입 인원·지출은 작업일지를 중심으로 한다. 지정 담당자의 공사 픽스 블록에 명시된 업체 실행비는 일정 메모와 추출 근거에 연결한다. 재수입 시 기존 일정의 금액 메모를 보완하되 동일 문구는 중복하지 않는다. 부가세·부분 금액·평당 단가·미정 조건을 유지하며 실제 지출이나 수주 원장에 자동 합산하지 않는다. 여러 문구가 있으면 최종 금액으로 자동 단정하지 않는다. 자유 대화의 최종 합의 판정 및 금액 변경의 시간순 정리는 아직 남아 있다.

### 단일 자료 입력 (후속 구현)

자료 가져오기는 카카오톡 TXT 또는 Markdown 한 파일만으로 시작할 수 있다. 두 파일을 함께 올리는 기존 경로도 유지한다. 실제로 올린 원본만 보존하며 추출 근거는 해당 원본에 연결한다. 빈 자료·인코딩 오류·2MB 초과를 입력 단계에서 안내한다.

Markdown은 현재 주소·내용·방문/공사 일정과 `2099년 9월 25일` 같은 연월일이 명시된 항목을 제한적으로 읽는다. 제목으로 분리되지 않은 복수 주소, 일반 표, 상대 날짜, 자유 문맥은 자동 해석하지 않는다. 추출 0건을 일정 없음으로 안내하지 않는다. 문서만으로 지정 담당자의 카톡 픽스와 동등한 신뢰를 만들어내지 않는다.

다음 우선 연결: 가져온 방문이 현장 없이 남아 수주 입력에 도달하지 못하는 경우 해결. 주소만 같은 현장을 무조건 합치지 말고, 원문 근거·기존 현장 식별·중복을 함께 다룬다. 그 뒤 일반 자유 문맥의 추출과 수주 저장 경계를 연결한다.

### 방문 → 수주 → 작업 연결 (후속 구현)

현장에 연결된 방문 상세에서 최종 수주 소식을 한 문장으로 입력한다. 현재 지원 예시는 `480만원에 메이드. 2026-09-20 08:00 작업 시작`이다. 작업일은 생략 가능하며 날짜를 포함하면 연도·월·일·시간을 명시한다. 이는 제한된 형식의 로컬 처리이지 범용 AI 문맥 분석이 아니다.

최종 기본 견적을 수주금액으로 저장하고, 기존 기본 견적이 하나면 변경 이력을 이어 대체한다. 제안 방문 견적 자체는 보존한다. 같은 현장의 작업 일정과 상태를 한 트랜잭션으로 연결한다. 기존 별도 작업 일정이 다른 날짜라면 임의로 덮어쓰지 않는다. 종료된 현장, 여러 기본 견적, 취소된 방문, 미연결 방문은 자동 처리하지 않는다. 동일 소식 재전송은 중복이나 이전 금액 복원으로 이어지지 않는다. 추가 견적·취소·복수 현장 문맥은 아직 이 입력에서 지원하지 않는다.

방문 결과는 자유 메모를 기본 입력으로 하고 세부 견적 항목은 선택적으로 펼친다. 기존 항목과 수정 이력은 유지한다. 현장 ID로 연결된 방문 결과·제안 견적은 현장 상세에서 다시 입력하지 않고 볼 수 있고, 예정 일정은 작업과 방문으로 구분한다. 제안 견적을 수주 매출로 전환하지 않는다.

아직 미구현: 미연결 방문의 현장 자동 식별, 일반 자유 메모의 견적·수주 자동 추출. 위 제한된 수주 소식 입력 외의 메이드 통합 반영은 남아 있다. 이번 연결만으로 전체 현장 흐름 완료를 선언하지 않는다.

## 0. 전체 사용 흐름과 다음 개발 기준 — 2026-09-10

이 절은 현재 Product의 최우선 구현 기준이다. 아래의 종전 본문, 9월 9일 구조 재정립 문서, 기존 상세 백로그와 충돌하면 이 절을 따른다. 종전 설계는 배경과 이력으로 보존한다. 인건비 세부 개선은 중단한다.

### 제품이 매일 해줘야 하는 일

황태환이 자료와 경험을 한 번 전달하면, Field Brain은 어느 현장에 어떤 변화가 있었는지 기억하고 다음 일정·작업·견적·비용 판단에 다시 사용한다. 첫 목표는 철거 사업 운영에 도움이 되는 것, 두 번째 목표는 이 과정에서 범용 현장 AI의 기반을 얻는 것이다.

대표 흐름: 자료 전달 → 현장 연결 → 견적 방문 → 견적 제안 → 수주(메이드) → 작업·변경·지출 → 작업 완료 → 다음 견적에 경험 재사용.

이 흐름은 화면마다 새로 입력하는 절차가 아니다. 이미 전달된 내용이 화면별로 다르게 보이는 구조다. 방문하지 않고 견적을 내거나, 수주 후 일정을 바꾸거나, 작업 중 범위를 추가하는 실제 경로도 허용한다.

### 다섯 화면의 역할

| 화면 | 사용자가 해결하는 질문 | 기본 노출 | 연결 |
|---|---|---|---|
| 오늘 | 오늘 어디에 가고 무엇을 챙길까? | 작업 일정, 견적 방문을 구분한 짧은 목록, 중요한 변경·준비 사항 | 현장/일정 상세와 자유 기록 |
| 일정 | 언제 작업하고 언제 견적 보러 갈까? | 달력과 선택 날짜 목록, 작업/방문 구분 | 같은 현장의 범위·주소·연락처 |
| 현장 | 이 현장은 어디까지 진행됐지? | 현재 범위, 최근 변화, 다음 일정, 남은 일, 아래쪽 돈 요약 | 방문 결과·견적·작업 기록·근거 |
| 기록 | 오늘 이야기와 자료를 어떻게 전달할까? | 자유 일지와 자료 전달을 구분한 두 진입점, 처리 결과 | 연결된 현장과 바뀐 내용 |
| 사업 | 어디에 돈이 들고 다음 견적에 무엇을 참고할까? | 현장별 수주금액·실제 투입비, 과거 사례·단가 | 현장 상세, 지출 장부, 현장 참고 |

새 최상위 메뉴는 추가하지 않는다. 오늘 화면에 전사 회계표를 펼치지 않는다. 사용자의 요청에 따른 돈 영역은 현장 맥락 아래에서 먼저 이해할 수 있도록 배치한다.

### 한 건을 처음부터 끝까지 검증하는 시나리오

아래는 실제 원장에 등록하지 않는 허구 시험 사례다. 날짜·금액은 시험용이며 시장 단가가 아니다.

| 단계 | 사용자가 전달하는 내용 | 앱이 연결해야 하는 결과 | 성공 판정 |
|---|---|---|---|
| 방문 약속 | 카톡 TXT 하나: “가상 새길상가 방문 일정 픽스, 9월 12일 11시” | 방문 일정과 현장 연결 | 추가 Markdown이나 수동 일정 재입력 없이 방문 달력에 나타남 |
| 방문 결과 | “가벽·바닥·간판 철거. 샷시는 보존. 고객에게 500만원 제안” | 고객 요청·제외 범위·제출 견적 | 500만원이 수주 매출로 합산되지 않음 |
| 수주 | “새길상가 480만원에 메이드. 14일부터 작업” | 수주금액 480만원, 작업 일정, 연결된 현장 상태 | 과거 500만원 견적과 480만원을 더하지 않음 |
| 작업 일지 | “새길상가 가벽 완료. 주유 7만원 지불. 오후엔 가상 푸른카페 견적 방문” | 새길상가 작업·실제 지출, 푸른카페 방문 기록 | 다른 현장 이야기가 새길상가 할 일·지출에 섞이지 않음 |
| 변경 | “간판은 보존하기로 변경. 바닥은 내일 이어서” | 현재 범위 변경, 남은 바닥 작업 | 과거 간판 철거 기록은 남고 현재 할 일에서는 빠짐 |
| 완료 | “새길상가 작업 모두 마침. 전체 실제 투입비 300만원, 기존 지출 포함” | 작업 완료와 비용의 포함 관계 확인 | 합계 300만원을 기존 개별 비용에 다시 더하지 않음 |
| 회고 | 다음 상가 견적에서 유사 사례 요청 | 범위·작업일·수주액·실제 지출·변경 근거를 함께 제시 | 480−300=180만원을 이 사례의 비용 범위에 한정해 설명 |

매 단계에서 정상 결과에는 승인 버튼을 요구하지 않는다. “거기 메이드”처럼 어느 현장인지 불명확하고 수주 판단을 바꾸는 경우에만 해당 문맥에서 한 가지 질문을 한다.

### 데이터와 AI가 연결하는 방식

- 원본 하나에는 여러 현장 이야기가 있을 수 있다. 원본은 한 번 보존하고, 문장·구간별 근거를 각 현장에 연결한다.
- 현장명이 바뀌거나 약칭으로 불려도 같은 현장 ID를 유지한다. 주소만 같다는 이유로 무조건 합치지 않는다.
- 고객의 요청 범위, 우리가 제안한 견적, 고객과 합의된 수주, 실제 작업 기록은 구분해서 저장한다.
- 현재 상태는 사건의 시간·취소·정정·추가 합의를 반영한 결과다. 최신 문장이라는 이유만으로 과거 사실을 덮어쓰지 않는다.
- 분석 결과는 일정·범위·비용·결정·남은 일을 한 처리 묶음으로 만든다. 적용 중 실패하면 재시도로 일부만 중복 저장되지 않아야 한다.
- 모델은 원문 근거와 해석을 제안하고, 앱이 현장 연결·중복·상태 변경·계산 규칙을 적용한다. 계산은 금액 단위와 포함 범위를 확인한 뒤 수행한다.
- 원본/실제 업무 데이터, 사용자의 수정 및 행동 데이터, 범용 제품 연구 데이터는 별도로 다룬다.
- GPT 대화와 앱의 호환은 같은 현장 ID·원문·정정 이력을 공유하는 가져오기/내보내기 규약으로 구현한다. 자동 동기화가 이미 된 것으로 안내하지 않는다.
- 첫 검증 입력은 자유 일지와 TXT/Markdown 텍스트다. 녹음·사진은 필요한 흐름에 순차 연결하며, 해석 기능이 없는 형식을 지원한다고 안내하지 않는다.

### 돈의 공통 의미

- 제출 견적은 잠재 매출이며 수주금액에 합산하지 않는다. 메이드/고객 합의가 특정 현장·견적 버전에 연결된 경우 수주금액으로 사용한다.
- 수주금액은 은행 입금액이 아니다. 계약금·중도금·잔금·미수금 추적은 범위 밖이다.
- 실제 투입비, 앞으로 들어갈 예상비, 작업자 일당으로 계산한 인건비는 서로 다른 값이다.
- 수주금액 − 현재까지 파악된 실제 투입비 = 현재까지 남은 금액. 작업과 비용 범위가 마무리된 경우에만 현장 수익으로 설명한다.
- 비용 미확인은 0원이 아니다. 일부 현장만 금액이 있는 합계를 전체 사업 수익처럼 표시하지 않는다.
- 개별 현장의 견적과 비용은 같은 현장끼리 비교한다. 수주 안 된 방문의 비용이나 공통 운영비를 합산할 때는 별도임을 표시한다.
- 지출 분류: 직접 인건비 / 외주비 / 장비비 / 폐기물 처리비 / 자재·소모품비 / 차량·이동비 / 식비·음료비 / 기타 비용.
- 중개수수료는 사용자 요청에 따라 제외한다. 이 기준으로 계산한 현장 수익을 모든 비용을 포함한 회계상 순이익으로 표현하지 않는다.
- 기사 포함 장비비·자재 포함 외주비·개별 비용을 포함한 합계는 한 번만 센다. 고물 판매는 지출과 별도 수입으로 보여준다.

### 코드 점검으로 확인한 현재 위치

점검은 실행 코드·화면 템플릿을 기준으로 했다. 아래는 전체 실제 업무 흐름의 통과 판정이 아니다.

| 연결 | 현재 확인한 구현 | 아직 끊긴 부분 |
|---|---|---|
| 자료 → 일정 | /schedule-import에서 TXT+Markdown 대조, 지정 담당자 픽스 등록 | 두 파일 필수. 단일 자료 및 다양한 자료의 통합 처리는 미완성 |
| 일지 → 현장 | /daily-log 자유 입력과 원문 보존, 한 현장 선택 | 여러 현장으로 문맥 분리하지 못함. 새 일지 현장을 작업 중으로 생성 |
| 현장 → 브리핑 | presenter.py, briefing.py의 발췌·할 일·일정 표시 | 범위 변경·다른 현장·완료 판단을 종합하는 브리핑 아님 |
| 방문 → 견적 | 방문 결과와 금액 저장 | 항목별 폼 부담. 수주 원장으로 이어지는 통합 흐름이 없음 |
| 견적 → 메이드 → 작업 | 합의 금액 계산 규칙, 작업 일정 각각 존재 | 메이드가 어떤 견적을 대체하고 현장 상태를 바꾸는지 연결하는 사용자 흐름 미완성 |
| 일지 → 지출 | direct_expenses.py의 명확한 지급 문장 자동 반영 | 제한된 표현만 지원. 여러 현장·합계·정정 문맥 처리 미완성 |

| 작업 완료 → 회고 | 기록·장부·현장 참고 존재 | 작업 완료와 비용 마무리 구분, 예상/실제 비교 및 다음 견적 재사용 흐름 미완성 |
| AI·GPT 호환 | ai_contract.py에 교환 규약과 검증 코드 | 이 파일은 모델을 호출하지 않음. 현재 앱의 문맥 분석 및 대화 동기화가 완성됐다고 볼 수 없음 |
| 제자리 수정 | 일정 수정·취소, 일부 금액 정정과 원문 이력 | 정상 업무에 후보/검토 경로가 여전히 남음. 통합 수정 흐름 미완성 |

### 2026-09-21 자료 전달 후 결과 확인

일정 자료를 올리면 처리 건수 아래에 이번 자료와 연결된 실제 일정이 나온다. 작업과 견적 방문을 분리하고 날짜·내용·저장된 상태·업체금액 조건을 보여주며 일정 상세와 같은 현장으로 바로 이동한다. 재업로드는 기존 일정을 중복 생성하지 않으면서 결과에 다시 보여준다. 과거 일정도 직접 열 수 있다. 원본과 DB는 공개하지 않는다.

이 목록은 저장된 현재 상태다. 후속 자유 대화의 변경·취소 해석이나 전체 MVP 완료를 의미하지 않는다. 업체금액은 실제 지출로 계산하지 않는다.

### 다음 개발 순서: 기능 묶음이 아닌 현장 흐름 완성

1. **자료에서 같은 현장 찾기:** TXT 또는 Markdown 하나와 자유 일지를 받아 근거별로 현장 연결. 중복·정정·복수 현장을 처리하고, 저장 후 어디에 무엇이 반영됐는지 보여준다.
2. **방문에서 수주·작업까지 연결:** 방문 결과 → 제출 견적 → 메이드 → 작업 일정이 같은 현장으로 이어진다. 수정 견적과 추가 견적, 수주 취소의 계산 결과까지 위 허구 시나리오로 검증한다.
3. **작업 변화가 현장 상황이 되게 하기:** 자유 일지에서 진행·범위 변경·남은 일·명확한 지출을 반영한다. 중요한 모호함만 문맥 안에서 질문하고 원문까지 한 번에 돌아간다.
4. **완료 현장을 다음 견적에 사용:** 비용 누락과 합계 중복을 구분하고, 결과를 과거 사례로 찾을 수 있게 한다. 공통 운영비·불명확한 비용을 포함하지 않은 수익은 그 범위를 설명한다.

각 단계에서 필요한 AI 연결은 그 단계의 대표 자료와 함께 구현·검증한다. UI에 AI 문구만 추가하거나 규칙을 늘린 것을 문맥 이해 완료로 부르지 않는다.

완료 조건은 위 대표 현장의 시작부터 끝까지 같은 내용을 다시 입력하지 않고 이어지는 것이다. 자동 테스트 개수와 개별 페이지 작동만으로 전체 제품 완료를 선언하지 않는다. 현재는 이 기준 미통과다.

이 네 단계가 연결되기 전 보류: 인건비 세부 예외, 급여 관리, 조직/권한 확장, 회계 ERP, 범용 업종 설정, 새 최상위 메뉴, 독립된 부가기능. 기존 원본·사용자 데이터·필요한 복구 기능은 유지한다.
